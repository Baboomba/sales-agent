# 화면 규칙

[코드 아키텍처](../../docs/convention/code-architecture.md) 6절 · [코드 컨벤션](../../docs/convention/code-style.md) 1 · 3절의 축약본이다. 다르면 그 문서가 맞다.

## 계층은 넷 — 위에서 아래로만 조립한다

| 계층 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `pages/` | 화면 하나. 아래 묶음을 배치한다 | 여러 화면이 쓰는 로직, 업무 판단 |
| `features/` | 한 일을 끝내는 UI. 조립 · 상태 · 순수 로직 · 서버 호출 | 화면 배치 |
| `entities/` | 업무 객체 하나를 그린다 | 상호작용 상태, 서버 호출 |
| `components/` | 도메인을 모르는 부품 | 업무를 아는 것 |

서버 호출은 `api/` 에만, 전역 상태는 `context/` 에만. 아래 계층은 위 계층을 import 하지 않는다.

## 묶음

* 렌더 `<묶음>.tsx` · 상태 `hooks.ts` · 순수 로직 `service.ts` · 스타일 `<묶음>.module.css` · 내보내기 `index.ts`. `hooks.ts` · `service.ts` 는 `features` 부터.
* 바깥은 `index.ts` 로만 가져다 쓴다. 제 폴더 밖은 `@/`.
* 무엇인지로 묶고, 쓰임새 · 화면 이름으로 묶지 않는다.

## 꼭 지킬 것

* **업무 모델을 두지 않는다.** 서버 DTO 타입(`api/types/`)을 그대로 쓰고, 판정 · 계산을 하지 않는다.
* **결과 숫자를 가공하지 않는다.** 천 단위 구분만 넣고 반올림 · 단위 변환을 하지 않는다 (NFR-002).
* 함수 · 컴포넌트는 화살표 함수로만(`function` 금지 — 린트가 막는다), 이름 있는 내보내기만. `as` 는 `api/` 의 JSON 경계에서만. `any` · `@ts-ignore` 금지.
* 스타일은 CSS Modules, 색 · 간격은 `index.css` 변수만. UI 라이브러리를 들이지 않는다.
* 테스트는 [테스트 규칙](../../docs/convention/testing.md) 7.2 — 사용자가 보는 것(역할 · 이름 · 글자)으로 찾고, 서버 응답을 짐작해 짓지 않는다.
