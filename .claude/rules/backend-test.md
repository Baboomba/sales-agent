# 서버 테스트 규칙

[테스트 규칙](../../docs/convention/testing.md)의 축약본이다. 다르면 그 문서가 맞다.

## 판정 기준

**구현을 통째로 다시 써도 통과하는가, 그리고 틀린 구현은 통과하지 못하는가.**

## 계층마다

| 계층 | 무엇을 보나 | 무엇 없이 | 자리 |
|---|---|---|---|
| 모델 | 테스트하지 않는다 (구조는 경계 검사) | — | — |
| 규칙 | 판정 | 의존성 · 프레임워크 | `tests/<도메인>/rules/` |
| 유스케이스 | 흐름 — 경로 · 낸 것 · 끝. 규칙의 판정을 다시 보지 않는다 | 가짜 의존성 | `tests/<도메인>/usecase/` |
| 의존성 구현 | 바깥을 모델 · 실패로 옮기는지 | DB · 파일에 닿으면 통합 | `tests/<도메인>/dependency/` · `tests/integration/` |
| API | 422, 모델 → DTO · SSE | 가짜 의존성으로 조립한 앱 | `tests/<도메인>/api/` |

가짜는 `tests/<도메인>/fake.py` 한 자리. 목 라이브러리를 쓰지 않는다. **언어 모델을 부르는 테스트를 쓰지 않는다** (NFR-005).

## 꼭 지킬 것

* 밖에서 관찰할 수 있는 것만 단언한다. 내부 호출 순서 · 횟수(설계가 정한 성질이 아니면), 구현의 문구 · 상수와 견주지 않는다.
* **기대값은 적는다.** 계산하지 않고, 입력에 있는 글자를 다시 찾지 않는다.
* **틀린 구현도 통과하는 단언을 쓰지 않는다** — `assert result` · `is not None` 만 보기, 고정 문구에 원래 있는 글자 찾기, 짝 없는 「없다」 · 「통과한다」.
* **입력도 틀린 구현을 갈라야 한다** — 기본값 · 실제 값 하나로만 보지 않는다, 찾을 대상을 처음 · 가운데 · 끝에 둔다, 판정에 쓸 필드 말고 다른 필드에서 답이 새지 않게 한다.
* 지적을 받으면 그 줄만이 아니라 같은 꼴을 범위 전체에서 고친다. **고친 줄에도 대조 목록을 다시 묻는다** ([검사 운영 규칙](../../docs/convention/review.md) 2절).
* **구현 뒤 `scripts/mutate.sh`** — 살아남은 변이가 고정 문구 · `assert_never` 갈래가 아니면 테스트가 빠진 것이다.
* 「잡는다」 「통과한다」는 실행해서 본 것만 말한다.
* 한 테스트는 한 사실. 테스트에 `if` · 반복 · 계산을 넣지 않는다. 가짜에 판단을 넣지 않는다.
* **N+1**: 목록을 다루는 자리는 항목 1개일 때와 여러 개일 때 바깥 호출 수가 **같은지만** 견준다. 몇 번인지 단언하지 않는다.
* 규칙 ID 는 테스트 이름이나 문서 문자열에, 그 규칙을 실제로 확인하는 테스트에만. 고정값의 가짜 ID 는 `ZZZ-R001`.
* `skip` 하거나 기대값을 결과에 맞추지 않는다.
