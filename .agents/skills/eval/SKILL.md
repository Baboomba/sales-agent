# 평가

모델 · 프롬프트를 바꾸는 판단은 느낌이 아니라 평가 세트의 숫자로 한다 (NFR-006).

## 순서

1. **모델 서버를 확인한다.** `curl -s $OLLAMA_BASE_URL/api/tags` 로 모델이 있는지 본다. 없으면 받을지 사용자에게 묻는다 — 모델은 수백 MB ~ 수 GB 다.
2. **실행한다.** `scripts/eval.sh <모델> [<모델> ...]`. 직접 python 을 부르지 않는다.
3. **기준과 비교한다.** `docs/eval/README.md` 의 직전 결과와 같은 문항 · 같은 지표로 비교한다.
   * 정답률: 실행 결과가 정답 SQL 의 결과와 같은 비율
   * 평균 시간: 질문 하나가 끝날 때까지
   * 재생성률: 첫 생성으로 끝나지 않은 비율
4. **틀린 문항을 읽는다.** 숫자만 보고 끝내지 않는다. 틀린 문항을 유형(매출 정의 · 날짜 · 집계 · 조인)으로 나눠 무엇을 고치면 될지 적는다.
5. **보고한다.** 결과 표와 해석을 보여 주고, `docs/eval/README.md` 에 남길지 묻는다.

## 평가 세트를 고칠 때

* 문항은 `backend/evaluation/questions.yaml` 에 있다. 정답 SQL 을 반드시 직접 실행해 결과를 확인한다.
* 문항을 빼서 점수를 올리지 않는다. 문항을 바꾸면 이유를 `docs/eval/README.md` 에 적는다.
