# 개발 환경 부트스트랩

환경 구성은 **반드시 스크립트로만** 한다(`scripts/bootstrap.sh`). 명령을 하나씩 손으로 부르지 않는다 — 순서가 있고(의존성 → 시드 → 모델 서버 → 모델 → 검사), 스크립트가 그 순서와 실패 안내를 갖고 있다.

## 흐름 셋

1. **실행** — 스크립트 하나
2. **보고** — 끝에 나온 안내를 근거로 무엇이 준비됐는지 알린다
3. **막히면 분석** — 아래 자주 겪는 문제로 원인을 짚고 다음 할 일을 말한다

## 1. 실행

**모델(약 1GB)을 처음 받는 경우면 먼저 사용자에게 묻는다.** 받기 싫다면 `--no-model` 로 돌린다.

```bash
scripts/bootstrap.sh              # 모두
scripts/bootstrap.sh --no-model   # 모델을 받지 않는다
scripts/bootstrap.sh --no-check   # 마지막 전체 검사를 건너뛴다
```

스크립트가 순서대로 하는 일 (여러 번 돌려도 결과가 같다 — 된 단계는 건너뛴다)

| 순서 | 하는 일 | 비고 |
|---|---|---|
| 1 | 준비물 확인 | git · uv · Node 24 이상 · npm. Python 3.13 은 uv 가 받는다 |
| 2 | git 훅 켜기 | `core.hooksPath` 를 `.githooks` 로 |
| 3 | 스킬 링크 확인 | `.claude/skills/*` 가 `.agents/skills/` 를 가리키는지. 끊겼으면 알리기만 한다 |
| 4 | 서버 의존성 | `uv sync` |
| 5 | 화면 의존성 | `npm ci` |
| 6 | 시드 데이터 | `backend/data/sales.db` 가 없으면 만든다 |
| 7 | 모델 서버 | 떠 있으면 그것을, 없으면 이 컴퓨터의 Ollama 를, 그것도 없으면 도커(컨테이너 `sales-agent-ollama`, 포트 11434)로 띄운다 |
| 8 | 모델 | `OLLAMA_MODEL`(기본 `qwen2.5-coder:1.5b`)이 없으면 받는다 |
| 9 | 전체 검사 | `scripts/check.sh` |

* **설정 파일을 만들지 않는다.** 설정은 모두 환경변수이고 기본값이 있다(`backend/app/config.py`). 비밀 값도 없다.
* 모델 서버 주소는 `OLLAMA_BASE_URL`(기본 `http://localhost:11434`)로 바꾼다.

## 2. 보고

* 어디까지 됐는지 — 단계마다 ✔ · ⚠
* 모델 서버를 무엇으로 띄웠는지 (이미 떠 있음 · 이 컴퓨터의 Ollama · 도커) — 도커면 GPU 없이 CPU 라 느리다고 알린다
* ⚠ 가 있으면 그 줄을 그대로 알린다 (모델을 받지 않음 · 스킬 링크 끊김 등)
* 다음 할 일: `scripts/serve.sh`(`serve` 스킬 — 화면 http://localhost:5173) · `scripts/check.sh` · `scripts/eval.sh`

## 3. 자주 겪는 문제

| 신호 | 원인 | 할 일 |
|---|---|---|
| `uv 가 없습니다` | uv 미설치 | 안내된 설치 명령을 사용자에게 알린다 — **직접 설치하지 않는다** |
| `Node 24 이상이 필요합니다` | 낮은 Node | Node 24 이상으로 바꾸게 안내한다 |
| `모델 서버를 띄울 수 없습니다` | Ollama 도 도커도 없음 · 도커가 꺼짐 | Docker Desktop 을 켜거나 Ollama 를 설치하고 다시 실행 |
| `도커의 모델 서버가 뜨지 않습니다` | 포트 11434 충돌 · 컨테이너 오류 | `docker logs sales-agent-ollama`, 11434 를 쓰는 다른 프로그램 확인 |
| `모델을 받지 못했습니다` | 인터넷 · 모델 이름 | 연결을 확인하고, `OLLAMA_MODEL` 을 바꿨다면 이름을 확인 |
| `끊긴 링크` | Windows 에서 심볼릭 링크 없이 받음 | `git clone -c core.symlinks=true` 로 다시 받기 (README 개발 절) |
| 전체 검사 실패 | 환경 또는 코드 | 실패한 단계의 출력을 그대로 보이고, 환경 문제(버전 · 네트워크)인지 코드 문제인지 가른다 |

## 하지 않는 것

* **데이터 · 볼륨을 지우는 명령을 스스로 부르지 않는다** — `docker compose down -v` · `docker volume rm` · 시드 DB 삭제는 사용자가 직접 실행한다(안내만 한다).
* **준비물을 대신 설치하지 않는다** — uv · Node · 도커 · Ollama 는 사용자가 설치한다.
* **운영 배포를 다루지 않는다** — 이 스킬은 로컬 개발 환경만 만든다. 한 줄 실행은 README 의 `docker compose up` 이다.
