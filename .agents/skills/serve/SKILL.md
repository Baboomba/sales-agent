# 서버 실행

서버 실행은 **반드시 스크립트로만** 한다(`scripts/serve.sh`). uvicorn · vite 를 손으로 부르지 않는다 — 모델 서버 확인, 뒤에서 띄우기, 둘 다 답할 때까지 기다리기, 내릴 때 자식 프로세스까지 내리기를 스크립트가 갖고 있다.

## 흐름 셋

1. **띄운다** — `scripts/serve.sh`
2. **보여 준다** — 브라우저에서 화면 주소를 연다
3. **막히면 분석** — 아래 자주 겪는 문제로 원인을 짚는다

## 1. 띄운다

```bash
scripts/serve.sh            # 띄운다 — 이미 떠 있으면 다시 띄우지 않는다
scripts/serve.sh --open     # 띄우고 이 컴퓨터의 기본 브라우저로 연다
scripts/serve.sh --status   # 떠 있는지
scripts/serve.sh --stop     # 내린다 (이 스크립트가 띄운 것만)
```

스크립트가 하는 일

| 순서 | 하는 일 | 비고 |
|---|---|---|
| 1 | 이미 떠 있는지 | 둘 다 떠 있으면 주소만 알리고 끝 |
| 2 | 준비 | 의존성이 없으면 멈추고 `scripts/bootstrap.sh` 를 안내. 시드 데이터가 없으면 만든다 |
| 3 | 모델 서버 | 떠 있으면 그것을, 없으면 이 컴퓨터의 Ollama, 그것도 없으면 도커로 띄운다. 모델이 없으면 알리기만 한다 — 받지 않는다 |
| 4 | 서버 · 화면 | `scripts/dev.sh` 를 뒤에서 띄우고 60초까지 기다린다. 기록은 `.run/serve.log` |

## 2. 보여 준다

* **에이전트에게 브라우저 도구가 있으면 그것으로 화면 주소(http://localhost:5173)를 연다** — 사용자가 대화 옆에서 바로 본다. 없으면 `scripts/serve.sh --open` 으로 기본 브라우저를 연다.
* 알릴 것 — 화면 주소, 쓰는 모델, 내리는 법(`scripts/serve.sh --stop`). ⚠ 가 있으면 그 줄을 그대로 알린다 (특히 모델 없음 — 화면은 뜨지만 질문하면 실패한다).
* 해 볼 만한 질문은 README 의 「해 볼 만한 것」 표에 있다.

## 3. 자주 겪는 문제

| 신호 | 원인 | 할 일 |
|---|---|---|
| `의존성이 없습니다` | 처음 받은 저장소 | `bootstrap` 스킬로 환경부터 갖춘다 |
| `포트 8000 · 5173 가운데 하나만 쓰이고 있습니다` | 다른 프로그램이 포트를 씀 | `lsof -iTCP:8000 -iTCP:5173 -sTCP:LISTEN` 으로 무엇인지 사용자에게 알린다 — **남의 프로세스를 끄지 않는다** |
| `60초 안에 뜨지 않았습니다` | 서버 오류 · 화면 빌드 오류 | 출력된 기록 끝 20줄로 원인을 짚는다 |
| `모델 서버를 띄울 수 없습니다` | Ollama 도 도커도 없음 · 도커 꺼짐 | Docker Desktop 을 켜거나 Ollama 를 설치 |
| `이 스크립트가 띄운 것이 아닙니다` | `scripts/dev.sh` 로 앞에서 띄움 | 그 터미널에서 내리게 안내한다 |
| 질문하면 「모델 서버에 연결할 수 없습니다」 | 모델 서버가 내려감 | `scripts/serve.sh` 를 다시 돌리면 모델 서버를 다시 띄운다 |

## 하지 않는 것

* **남이 띄운 프로세스를 끄지 않는다** — `--stop` 은 이 스크립트가 띄운 것만 내린다.
* **모델을 받지 않는다** — 받는 일은 사용자에게 묻고 `bootstrap` 스킬로 한다(약 1GB).
* **운영 배포를 다루지 않는다** — 한 줄 실행은 README 의 `docker compose up` 이다.
