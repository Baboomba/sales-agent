# 구현

한 차례는 설계서의 규칙 하나 또는 흐름 하나다. 여러 규칙을 한꺼번에 하지 않는다.

## 순서

1. **설계서를 읽는다.** `docs/design/` 에서 대상 규칙과 4절 테스트 사항을 찾는다. 없으면 멈추고 `design` 스킬로 넘긴다.
2. **테스트를 쓴다.** 테스트 사항 표의 "확인" 을 그대로 테스트로 옮긴다.
   * 층은 표의 "층" 을 따른다. 규칙 ID 를 테스트 이름이나 문서 문자열에 적는다.
   * 작성 규칙은 `.claude/rules/backend-test.md` 다.
3. **⏸ 승인 1** — 쓴 테스트 목록과 각 테스트가 확인하는 사실을 보고한다. 승인 전에는 구현하지 않는다.
4. **실패를 확인한다.** `scripts/test.sh` 로 돌려 **새 테스트가 기대한 이유로** 실패하는지 본다. import 오류로 실패하는 것은 기대한 실패가 아니다.
5. **구현한다.** 테스트를 통과하는 가장 단순한 코드. 설계서에 없는 동작을 더하지 않는다.
6. **검사한다.** `scripts/check.sh` 전체가 통과해야 한다 — 린트 · 포맷 · 타입 · 계층 경계 · 규칙 커버리지 · 테스트.
7. **설계와 대조한다.** 구현이 설계서와 어긋난 곳이 있으면 코드가 아니라 설계서가 맞는지부터 사용자에게 묻는다.
8. **⏸ 승인 2** — 바뀐 파일, 검사 결과, 설계와 어긋난 점을 보고한다. 승인이 곧 커밋 지시다.

## 금지

* 테스트를 결과에 맞춰 고치기, `skip`, 검사 우회 — `AGENTS.md` 「검사를 우회하지 않는다」
* 언어 모델을 부르는 테스트 — 모델 품질은 `eval` 스킬이 잰다
