# 요구사항 명세

매출 데이터에 자연어로 질문하면, Agent 가 SQL 을 만들어 검증하고 실행해 결과를 표로 돌려주는 서비스다. 설계서와 코드는 이 문서를 근거로 한다.

## 용어

* **질문**: 사용자가 한국어로 적은 물음. 예: "2025년 지역별 매출 상위 3곳은?"
* **Agent**: 질문을 받아 SQL 생성 → 검증 → 실행을 단계별로 수행하는 처리 흐름. LangGraph 그래프로 만든다.
* **생성**: 언어 모델이 질문과 스키마를 보고 SQL 한 문장을 만드는 일.
* **검증**: 만든 SQL 이 실행해도 안전한지 코드가 판정하는 일. 모델이 아니라 규칙이 한다.
* **재생성**: 검증이나 실행에 실패했을 때, 실패 사유를 붙여 모델에게 다시 만들게 하는 일.
* **평가 세트**: 정답 SQL 이 붙은 질문 묶음. 모델과 프롬프트의 품질을 숫자로 잰다.

## 1. 전제

| 항목 | 내용 |
|---|---|
| 사용자 | 이 저장소를 받아 직접 띄워 보는 검토자. GPU 가 없는 노트북일 수 있다 |
| 설치 | `docker compose up` 한 줄로 뜬다. 따로 설치할 DB 서버가 없다 |
| 언어 모델 | 로컬 Ollama 의 작은 모델만 쓴다. 유료 API 를 쓰지 않는다 |
| 데이터 | 가상의 2025년 매출 데이터. SQLite 파일 하나다. 저장소에는 파일 대신 시드 스크립트를 두고, 이미지를 만들 때 같은 시드로 만든다 |
| 범위 | 조회만 한다. 데이터를 바꾸는 기능은 없다 |

## 2. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FR-001 | 사용자가 한국어 질문을 보내면 SQL 을 만들어 실행하고 결과를 표로 돌려준다 |
| FR-002 | 생성 → 검증 → 실행의 진행 상황을 단계마다 화면에 보여준다 |
| FR-003 | 실행한 SQL 을 사용자가 볼 수 있다 |
| FR-004 | 검증이나 실행에 실패하면 사유를 붙여 다시 생성한다. 횟수에 한도가 있다 |
| FR-005 | 끝내 실패하면 무엇 때문에 실패했는지 사용자에게 알린다 |
| FR-006 | 사용자가 어떤 표와 열이 있는지 볼 수 있다 |
| FR-007 | 처음 쓰는 사용자를 위해 예시 질문을 제공한다 |

## 3. 비기능 요구사항

| ID | 요구사항 |
|---|---|
| NFR-001 | **데이터를 바꾸는 SQL 은 어떤 경우에도 실행되지 않는다.** 모델이 무엇을 내든 막는다 |
| NFR-002 | 결과의 숫자를 모델이 다시 말하지 않는다. 숫자는 DB 가 낸 그대로 표로만 보인다 |
| NFR-003 | GPU 없는 CPU 환경에서 질문 하나가 1분 안에 끝난다 |
| NFR-004 | 한 번에 돌려주는 행 수와 실행 시간에 상한이 있다 |
| NFR-005 | 테스트는 언어 모델 없이 돈다. CI 에 모델 서버를 띄우지 않는다 |
| NFR-006 | 모델 선정은 평가 세트로 잰 숫자를 근거로 한다 |
| NFR-007 | 설계서의 규칙마다 대응 테스트가 있다. 빠지면 검사가 실패한다 |
| NFR-008 | 내부 정보(시스템 표 · 스키마 정의 · 서버의 파일 경로)를 결과로 내보내지 않는다 |

## 4. 하지 않는 것

| 항목 | 사유 |
|---|---|
| 결과 요약 문장 | 작은 모델은 숫자를 옮기다 틀린다(NFR-002). 표가 곧 답이다 |
| 대화 이어가기 | 질문 하나가 독립된 요청이다. 이전 질문을 기억하지 않는다 |
| 로그인·권한 | 검토용 단일 사용자 서비스다 |
| 질의 이력 저장 | 범위를 하루 안에 끝낼 크기로 지킨다 |
