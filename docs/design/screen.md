# 화면(screen) 설계서

질의 화면 하나의 설계다. 서버 흐름과 응답 모양은 [질의 설계서](query.md)가, 화면 코드를 나누는 법은 [코드 아키텍처](../convention/code-architecture.md) 6절이 갖는다. 시안은 `docs/design/screen-mockup.html` 이다 (PC · 휴대폰 반응형).

## 1. 목적

### 다루는 것

* 질문하기와 예시 질문 (FR-001 · FR-007)
* 단계별 진행과 재생성 (FR-002 · FR-004), 실행한 SQL (FR-003), 실패 사유 (FR-005)
* 표와 열 (FR-006)
* 칸의 크기 · 위치를 고정하는 법, 휴대폰 배치

### 용어

* **칸** — 화면을 나눈 고정 크기의 영역이다. 표와 열 · 질문 · 결과 · 처리 기록이 각각 칸이다.
* **진행 표시** — 응답을 기다리는 동안 보이는 「진행 중」과 「중지」 단추다.
* **처리 기록** — 질의 단계(질의 설계서 2.2)를 일어난 순서대로 세로로 쌓은 것이다.
* **단계 칸** — 생성 · 검증 · 실행 셋의 지금 상태를 가로로 보이는 세 칸이다.

### 다루지 않는 것

* 결과 요약 문장 · 대화 이어가기 · 로그인 — 요구사항 4절
* 서버가 무엇을 내는지 — 질의 설계서

## 2. 배치

### 2.1 넓은 화면 (폭 1024px 이상)

**틀의 높이는 800, 폭은 창에 맞추되 1280 을 넘지 않는다.** 표와 열(260)과 처리 기록(320)은 폭이 고정이고, 가운데 칸만 창 폭을 따른다(1024 에서 444, 1280 에서 700). 가로 스크롤은 생기지 않는다. 칸의 크기는 창 폭으로만 정해지고 내용 · 상태로는 바뀌지 않는다 (SCR-R001).

```text
┌──────────────────── 상단바 (최대 1280) × 64 ─────────────────────┐
│ 이름 · 모델 이름                                                  │
├──────────┬──────────────────────────────────┬────────────────────┤
│ 표와 열   │ 질문칸 + 질문하기        52       │ 처리 기록           │
│ 260      │ 예시 질문 (줄바꿈) 32 × 줄 수      │ 320                │
│          │ 단계 칸 (생성·검증·실행)  72       │  요약 (시도·다시    │
│          │ 결과 카드 (나머지 높이)            │   만듦·행)          │
│          │  탭: 표 · 실행한 SQL              │  세로 기록           │
│          │ 444 ~ 700 (창 폭을 따름)           │                    │
└──────────┴──────────────────────────────────┴────────────────────┘
                           본문 높이 736
```

### 2.2 좁은 화면 · 휴대폰 (폭 1023px 이하)

위에서부터 한 줄로 쌓는다. 높이는 칸마다 고정이다. 가운데 칸이 444 보다 좁아지면 단계 칸 세 개와 질문칸이 들어가지 않으므로, 넓은 화면 배치는 1024 부터 쓴다.

| 칸 | 높이 |
|---|---|
| 상단바 | 56 |
| 질문칸 + 질문하기 | 48 |
| 예시 질문 — 줄바꿈해 모두 보인다 | 32 × 줄 수 |
| 단계 칸 | 64 |
| 탭: 결과 · 처리 기록 · 표와 열 | 44 |
| 고른 탭의 칸 — 하나만 보인다 | 480 |

### 2.3 상태마다 무엇이 보이나

| 상태 | 단계 칸 | 결과 카드 | 처리 기록 | 질문하기 단추 |
|---|---|---|---|---|
| 묻기 전 | 셋 다 대기 | 안내 문구 | 비어 있음 안내 | 질문하기 (공백뿐이면 누를 수 없음) |
| 묻는 중 · 300ms 안 | 앞 질문 그대로 | 앞 질문 그대로 | 앞 질문 그대로 | 질문하기 그대로 |
| 묻는 중 · 300ms 넘음 | 받은 만큼 + 진행 중 | 진행 중 | 받은 단계 + 진행 중 | 중지 |
| 완료 | 셋 다 완료 | 표 | 끝까지 | 질문하기 |
| 실패 | 실패한 단계에 실패 | 실패 사유 알림 | 끝에 실패 사유 | 질문하기 |
| 중지 | 셋 다 대기 | 안내 문구 | 비어 있음 안내 | 질문하기 |

## 3. 화면 규칙

| ID | 규칙 | 위반 시 |
|---|---|---|
| SCR-R001 | 칸의 위치와 크기는 내용 · 상태에 따라 바뀌지 않는다. 내용이 넘치면 그 칸 안에서 스크롤한다 | 칸이 늘었다 줄며 화면이 깜빡이고, 표와 열이 밀려난다 (#63) |
| SCR-R002 | 진행 표시(진행 중 · 중지)는 응답이 300ms 를 넘길 때만 보인다 | 빠른 응답에 진행 표시가 번쩍인다 |
| SCR-R003 | 새로 물어도 첫 단계가 올 때까지 앞 질문의 결과를 그대로 두고, 첫 단계가 오면 한 번에 바꾼다. 300ms 가 지나도 첫 단계가 없으면 그때 비우고 진행 표시를 보인다 | 칸이 비었다 차며 깜빡인다 |
| SCR-R004 | 묻는 동안 질문하기 단추의 모양을 바꾸지 않는다(끄지 않는다). 두 번 보내기는 막는다 | 단추가 흐려졌다 돌아와 깜빡인다 · 같은 질문이 두 번 나간다 |
| SCR-R005 | 질문칸은 300자까지 받고(QRY-R001), 앞뒤 공백을 뺀 글이 없으면 질문하기를 누를 수 없다 | 서버가 422 로 거부할 질문을 보낸다 |
| SCR-R006 | 예시 질문을 누르면 그 질문을 질문칸에 넣고 바로 묻는다. 고른 예시는 강조한다 | 처음 쓰는 사용자가 무엇을 물을지 모른다 (FR-007) |
| SCR-R007 | 단계 칸은 생성 · 검증 · 실행마다 대기 · 진행 · 완료 · 실패를 보인다. 생성 칸에는 시도 번호와 다시 만든 횟수를 적는다 | 어디까지 왔는지 모른다 (FR-002) |
| SCR-R008 | 처리 기록은 질의 단계를 일어난 순서대로 하나씩 쌓는다. 거부됨은 실패한 단계(생성 · 검증 · 실행)와 사유를 함께 보인다. 맨 위에 시도 수 · 다시 만든 수 · 행 수를 요약한다 | 왜 다시 만들었는지 모른다 (FR-004) |
| SCR-R009 | 결과 카드의 「실행한 SQL」 탭은 검증됨의 SQL(실행되는 글 그대로)을 보인다. 검증 전이면 마지막 생성됨의 SQL 을 「만든 SQL」로 보인다 | 실행하지 않은 SQL 을 실행한 것으로 보인다 (FR-003) |
| SCR-R010 | 실패하면 결과 카드 자리에 실패 사유를 알림으로 보이고(스크린 리더가 읽게), 처리 기록 끝에도 남긴다. 그때까지 만든 SQL 은 남긴다 | 왜 실패했는지 모른다 (FR-005) |
| SCR-R011 | 결과 표의 숫자는 천 단위 구분만 넣고 반올림하지 않으며 오른쪽 정렬한다. 행 번호는 DB 가 낸 순서다. 잘렸으면 앞부분만 보인다고, 행이 없으면 데이터가 없다고 알린다 | 숫자 왜곡 (NFR-002) · 잘렸는지 모른다 (QRY-R005) |
| SCR-R012 | 결과에 숫자 열이 하나뿐이고 값이 모두 0 이상이면, 그 열 옆에 최댓값에 견준 막대를 그린다. 막대는 그림일 뿐 숫자를 바꾸지 않는다. 그 밖에는 그리지 않는다 | 음수 · 여러 숫자 열에서 막대가 뜻을 잘못 전한다 |
| SCR-R013 | 표와 열은 DB 의 순서대로, 표마다 업무 설명과 열(이름 · 설명)을 보인다. 처음에는 첫 표를 펼쳐 둔다 | 어떤 표에 물을 수 있는지 모른다 (FR-006) |
| SCR-R014 | 표와 열 · 예시 질문 · 모델 이름을 못 불러오면 그 칸에 「불러오지 못했습니다」와 다시 시도 단추를 보인다 | 칸이 아무 말 없이 빈다 (#60) |
| SCR-R015 | 좁은 화면(폭 1023px 이하)에서는 결과 · 처리 기록 · 표와 열을 탭으로 나누고, 고른 하나만 같은 고정 높이 칸에 보인다. 처음 탭은 결과다 | 휴대폰에서 칸이 길게 늘어져 질문칸이 화면 밖으로 밀린다 |

**SCR-R002 · R003 을 정한 근거.** 진행 표시를 묻는 즉시 켜면, 모델 서버가 없어 30ms 만에 실패하는 경우에도 단추와 진행 줄이 바뀌었다 돌아와 깜빡였다(#63). 300ms 는 사람이 「기다렸다」고 느끼기 시작하는 길이다.

**SCR-R012 를 좁힌 근거.** 시안은 지역별 매출처럼 「글 열 하나 + 숫자 열 하나」를 그렸다. 결과의 모양은 질문마다 다르므로, 막대가 뜻을 잘못 전하지 않는 경우에만 그린다.

## 4. 화면 테스트 사항

층은 [테스트 규칙](../convention/testing.md) 7.2 의 계층이다 — entities · features · pages. 화면 규칙의 커버리지는 화면 테스트 이름에서 센다(검사를 넓히는 일은 구현 차례에서 한다).

| 규칙 | 확인 | 층 |
|---|---|---|
| SCR-R001 | 묻기 전 · 묻는 중 · 완료 · 실패에서 칸의 자리가 같다 (렌더 결과에 칸이 늘 있다). 크기 자체는 브라우저에서 잰다 | pages |
| SCR-R002 | 300ms 안에 끝나면 진행 중 · 중지가 한 번도 보이지 않는다. 늦으면 보인다 | features |
| SCR-R003 | 다시 물으면 첫 단계가 올 때까지 앞 결과가 남고, 늦으면 지워진다 | features |
| SCR-R004 | 묻는 동안 질문하기 단추가 꺼지지 않는다. 진행 중에 다시 물어도 한 번만 보낸다 | features |
| SCR-R005 | 300자 상한, 공백뿐이면 질문하기를 누를 수 없다 | features |
| SCR-R006 | 예시를 누르면 질문칸에 들어가고 그 질문을 보낸다. 고른 예시가 강조된다 | features |
| SCR-R007 | 재생성 · 완료 · 실패마다 단계 칸의 상태와 시도 번호 · 다시 만든 횟수 | entities |
| SCR-R008 | 단계를 받은 순서대로 쌓고, 거부됨에 단계와 사유가 있다. 요약 숫자 | entities |
| SCR-R009 | 검증됨이 있으면 그 SQL 을 「실행한 SQL」로, 없으면 마지막 생성됨을 「만든 SQL」로 | features |
| SCR-R010 | 실패 사유가 알림으로 보이고 처리 기록 끝에도 있으며, 만든 SQL 이 남는다 | features |
| SCR-R011 | 천 단위 구분 · 반올림 없음 · 오른쪽 정렬 · 잘림 안내 · 빈 결과 안내 | entities |
| SCR-R012 | 숫자 열 하나 · 0 이상이면 막대가 있고, 숫자 열이 둘이거나 음수가 있으면 없다 | entities |
| SCR-R013 | DB 순서, 설명, 첫 표만 펼쳐 있다 | entities |
| SCR-R014 | 표와 열 · 예시 · 모델 이름을 못 불러오면 그 칸에 안내와 다시 시도가 있고, 다시 시도하면 다시 부른다 | features |
| SCR-R015 | 탭을 고르면 그 칸만 보이고, 처음은 결과다 | pages |

## 5. 상태와 의존

### 5.1 화면에만 있는 상태

| 상태 | 자리 | 뜻 |
|---|---|---|
| 질문 | 질문하기의 `hooks.ts` | 입력 중인 글 |
| 단계 목록 · 진행 중 · 늦음 | 질문하기의 `hooks.ts` | 받은 질의 단계, 응답을 기다리는지, 300ms 를 넘겼는지 (SCR-R002 · R003) |
| 고른 휴대폰 탭 | 질의 화면(`pages/Query`) | 결과 · 처리 기록 · 표와 열 (SCR-R015) |

서버에서 온 것(단계 · 표와 열 · 예시 · 모델 이름)은 응답 타입(`api/types/`)을 그대로 쓴다. 판정 · 계산을 하지 않는다 — 막대 길이(SCR-R012)와 요약 숫자(SCR-R008)는 보여 주기 위한 손질이다.

### 5.2 서버

| 주소 | 화면이 쓰는 곳 |
|---|---|
| `POST /api/queries` | 질문하기 — 질의 단계를 SSE 로 받는다 (질의 설계서 2.2) |
| `GET /api/schema` | 표와 열 (질의 설계서 2.4) |
| `GET /api/examples` | 예시 질문 |
| `GET /api/health` | 상단바의 모델 이름 |

### 5.3 계층에 놓는 자리

| 화면 조각 | 계층 |
|---|---|
| 폭 1280 까지의 틀, 세 칸 배치, 휴대폰 탭 | `pages/Query` |
| 질문칸 · 예시 · 단계 칸 · 결과 카드 · 처리 기록 | `features/AskQuery` — 한 상태(질의 단계)를 함께 쓰므로 한 기능이다. 화면이 넘긴 탭에 따라 휴대폰에서 결과 카드나 처리 기록 가운데 하나만 보인다 |
| 표와 열 | `features/TableList` |
| 모델 이름 | `features/ModelStatus` |
| 단계 칸 · 처리 기록 · 결과 표 · 표와 열 그리기 | `entities/query/*` · `entities/schema/*` |
